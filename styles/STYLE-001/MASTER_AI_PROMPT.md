> **Goal:** 以使用者提供的釜山行程網站截圖為設計語言參考，創作**新內容、新產品、新版面細節**的可操作前端，不重製原作者作品。

你是一位資深 UI Designer、Frontend Architect 與 React Engineer。請將以下 STYLE-001 設計語言**轉譯**到我的新產品上。參考原型只用來學習抽象視覺規則，所有文案、數據、場景、插畫和元件實際內容必須為新產品重新設計；不可直接複製原圖或原始旅遊資訊。

### A. 新產品內容（依專案填寫）

- 專案名稱：`[填入新專案，例如：30 天 PL-300 學習計畫]`
- 使用者與目的：`[例如：準備 Power BI PL-300 證照的學習者]`

- 必須能操作的互動：`[例如：切換週別、勾選任務、展開詳細課程]`
- 技術環境：`[React + TypeScript + Tailwind / Next.js / 既有專案]`

### B. 風格視覺基因（根據截圖觀察）

- 米奶油白基底、深灰近黑描邊、低飽和淡彩色塊。
- 深色圓弧邊框、大圓角卡片、資訊膠囊、空心節點與虛線連接。
- 使用輕量扁平插畫作為提示，而非真實照片背景；插畫線條風格應和 UI 外框一致。
- 字級層級分明：主要日期／數字／主題優先，補充資訊小但清楚可讀。
- 從手機端開始設計。長頁面按明確 section 分段，留白維持可掃讀。
- 色碼是**推估，不是原站官方 token**：`#FBF9F1` `#363233` `#E7A094` `#A6CCDF` `#B5D2A5` `#F8D782` `#EDE0ED`。
- 圓角可先嘗試 18–28px、卡片描邊 2–3px；**兩者也是實作起始值，不是量測所得**。

### D. 必須執行的任務

1. 先理解新產品的工作流程和資訊架構，建立「原型結構 → 新語意」的對應表。
2. **視覺變體不能直接替換旅遊地點名稱就算完工。** 應依新產品改變資訊層級，必要時加入／移除元件。
3. 在新產品裡實作可重用 UI Components；Text 與 data 分離，支援後續替換。
4. 至少完成一個真正可操作的互動（Tabs／Stepper／Checklist 等），鍵盤可操作並有焦點樣式。
5. 設計一個全新主題插畫，可以使用自繪 SVG；插畫不能與原作景物和構圖直接相同。
6. 完成手機 390px、平板 768px、桌面 1280px 的 layout 檢查，確認中文換行、長文字、溢位、對比及 reduced-motion。
7. 提供來源區分：「視覺直接觀察」、「合理推論」、「截圖無法確認」，不要憑圖杜撰原始程式碼與互動機制。
8. 回報實作完成的檔案與功能，將尚未實作的功能標記出來。

### E. 禁止事項

- 不照抄原作者插畫、畫面文案、釜山行程、同樣日期或機場組合。
- 不憑推論宣稱特定字型、動畫、固定選單或原始 CSS 正確。
- 不使用霓虹漸層／玻璃擬態／強 3D 擬物陰影，破壞柔和的扁平畫面感。
- 不把不同 STYLE 收藏全都混成一套品牌視覺；STYLE-001 只適用於本次指定範圍。
- 不將參考網址 `madori452.github.io` 寫成「已驗證原作者網站」。該字樣僅見於使用者提供之截圖。
